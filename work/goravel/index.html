Goravel

I contribute to the Goravel Go framework regularly. My merged work includes embedded filesystems as view sources, first-party frontend tooling, and a view function registry. Modules for building apps DDD-style are in review.

Embedded filesystem for views (#1546): packages can ship their templates inside the binary with go:embed and register them with View.LoadViewsFromFS, with a clear precedence between app views, directories and embedded filesystems.

Frontend tooling (#1603, +2,309 lines): first-party Vite support modelled on Laravel's @vite directive, with vite, viteAsset and viteReactRefresh template functions, plus a vite:inputs command that the companion goravel-vite-plugin npm package reads.

View function registry and compile bridge (#1589): template helpers no longer need driver-specific config, and every view is compiled after all providers boot, so registration order no longer matters.

Modular DDD (#1613, +9,859 lines, in review): a module is a Go package that groups one feature (providers, routes, views, translations, config, migrations, commands). Everything except Name() is an optional interface, and an app without modules builds exactly as before.

Also merged: before/after hooks for Artisan commands, and WithCommandsFilter applied across the built-in command groups.
